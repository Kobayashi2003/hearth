## 一、总览

Hearth 是**一台 Windows 机器、一个主人**的自托管文件服务器：文件留在家里的硬盘上，网络只负责"访问"（浏览、查看、管理），不负责托管、同步或备份。

Node 22 + Fastify 5，TypeScript（ESM，`tsc -b` 编译到 `server/dist`）。约 6,700 行。

决定代码形状的几条约束：

- **字节路径上没有第二个进程。** 前端是 Caddy 直接吐出的静态文件；`<video src>` 指向 `/hearth-api/media/raw`，Caddy 以 `flush_interval -1` 把 Range 请求原样转给后端。没有前端服务器替你缓冲、掉线。
- **路径安全是类型，不是审查项。** 用户给的每个路径都必须经过 `request.resolvePath()`：它把路径解析进当前根目录、检查权限，返回一个带品牌的 `SafePath`。所有碰文件系统的 service 只接收 `SafePath`，没证明过的路径在类型上就到不了 `fs`。
- **分层由 lint 强制**：`routes → services → adapters → lib`。route 不许 import `node:fs` / `node:child_process`；adapter 不许 import `modules/`。
- **启动配置冻结，运行时可改的另放。** `AppConfig` 在启动时从环境变量构建并 `deepFreeze`；管理员能在运行中改的（当前根、仅管理员模式、回收站开关、HTML 查看器开关）放在 `RuntimeState`，每个读者每次使用时现取，所以切换根目录不需要任何缓存失效。
- **搜索外包给 Everything。** 不自建索引；Everything 不可达或不在 Windows 时自动降级为 worker 线程里的目录遍历，搜索永不硬失败。

### 部署拓扑

```
Internet ─► frp ─► :30709 Caddy ─┬─► /hearth/*      → web/dist 静态文件
                                 └─► /hearth-api/*  → 后端 127.0.0.1:17010（只听回环）
                                                       ├─ Everything HTTP（回环）
                                                       └─ ffmpeg / ffprobe 子进程
```

`start.ps1` 启动后端 + Caddy；`-NoCaddy` 时由外部的共享边缘占用端口，路由都在 `Caddyfile.snippet`。开发时 `npm run dev` 同时跑后端（tsx watch）和 Vite（:17011，代理 `/hearth-api`）。

### 子系统名（代码与日志里使用）

| 名字 | 管什么 |
|---|---|
| **Vault** | 根目录、路径解析与包含检查、列目录、文件操作、上传下载 |
| **Beacon** | 文件名搜索（Everything / 目录遍历两个 provider） |
| **Kiln** | 把磁盘上的文件变成浏览器能显示的东西：Range 流、转码、缩略图、漫画/Office/PSD/HTML 渲染 |
| **Warden** | 登录、会话、用户、按路径的权限、媒体令牌 |
| **Ember** | 回收站 |
| **Ledger** | 每个用户"看到哪了"：进度 + 阅读器会话 |
| **Hob** | 每个用户的偏好（主题、密度、视图……） |
| **System** | 版本、健康、根目录切换、管理员开关、缓存清理 |

## 三、逐模块

每个 `modules/<name>/` 由 `routes.ts`（校验输入、检查权限、编排）和若干 `*.service.ts`（业务）组成。所有路由挂在 `HEARTH_API_PREFIX`（默认 `/hearth-api`）下。

路由 `config` 的两个字段决定鉴权：`auth`（`session` 默认 / `public` / `media-token`）与 `permission`（全局动词 `read` / `write` / `delete` / `admin`）。按路径的检查则在 `request.resolvePath(path, action)` 里完成。

### 3.1 Warden —— 身份与权限

| 文件 | 职责 |
|---|---|
| `warden.ts` | 门面：登录（仅管理员模式下拒绝非管理员）、登出、解析会话、吊销某用户全部会话、`can` / `assertCan`、签发与校验媒体令牌与站点令牌；`siteSession`：站点请求以令牌用户**当前**的状态行事——用户已删除则拒绝、仅管理员模式下非管理员被拒、按其现在的权限检查（站点路由是公开路由，不经过认证插件的这些检查） |
| `user-directory.ts` | 两类用户的并集：`HEARTH_USER_RULES` 里的静态用户（只读，密码可明文可 bcrypt）与 `users.json` 里管理界面建的用户（bcrypt）。未知用户也做一次同耗时的 bcrypt 比较，登录时间不泄露用户名是否存在 |
| `permissions.ts` | 按路径的 ACL（`permissions.json`）：`/a/**`、`/a/*`、裸路径前缀、精确匹配；按具体程度 → 指名用户优先于 `*` → deny 优先于 allow 排序，第一条胜出；无规则时用用户自己的权限串。`w` 隐含 `d` |
| `session-store.ts` | 会话存储：内存（带过期清扫）或 Redis（可选依赖，连不上自动退回内存并告警）；Redis 另维护每用户会话集合以便吊销 |
| `media-token.ts` | HMAC 令牌：绑定用户、单个路径、当前根目录与过期时间，用于不能带 cookie 的场景 |
| `routes.ts` | `POST /auth/login`、`POST /auth/logout`、`GET /auth/session`、`POST /media/token` |

### 3.2 Vault —— 浏览与文件操作

| 文件 | 职责 |
|---|---|
| `listing.service.ts` | 读目录（stat 并发上限 64，隐藏 `$RECYCLE.BIN` 等系统条目，以及 macOS 与 Windows 留在文件旁边的元数据：`._xxx`、`.DS_Store`、`__MACOSX`、`Thumbs.db`、`desktop.ini` 等；搜索与文件夹封面用同一个判断）、描述单个路径、`require` / `assertDirectory` / `assertFile` |
| `routes.ts` | `GET /files`：整个目录一次返回（排序在服务端，上限 20,000 条，超出时 `hasMore`）；导出共用的 `listingQuerySchema` |
| `fileops.service.ts` | 新建文件夹、重命名（纯大小写变更不算冲突）、批量复制/移动（逐项报告结果；禁止移进自身；跨卷时复制后删除）、永久删除；`resolveCollision` 按 Windows 习惯加 " (2)" |
| `fileops.routes.ts` | `POST /fs/mkdir`、`/fs/rename`、`/fs/copy`、`/fs/move`、`DELETE /fs`（回收站开启时移入 Ember）。重命名、移动时调用 `ledger.reprefix`，永久删除时 `ledger.forget` |
| `upload.service.ts` | 把一个上传流写到目标目录：相对路径逐段校验（文件夹上传）、大小上限、可选的魔数校验（内容与扩展名矛盾才拒绝）、失败时删掉半截文件 |
| `chunked-upload.service.ts` | 可续传分片上传：每片一个文件，`status` 报告已收到哪些片，`complete` 顺序拼接成流；会话归属创建者；过期会话定时清扫 |
| `download.service.ts` | 多文件 / 文件夹打包下载：先换一张 5 分钟一次性票据，再用普通导航下载（浏览器自己管保存对话框）；ZIP 边压边发，内存占用恒定 |
| `transfer.routes.ts` | `POST /upload`（多文件，字段名携带相对路径）、`/upload/chunked/*`、`GET /download`、`POST /download/zip`、`GET /download/zip/:token` |

### 3.3 Beacon —— 搜索

| 文件 | 职责 |
|---|---|
| `beacon.ts` | 选 provider（`auto` / `everything` / `walk`），探活结果按冷却期缓存并去重；Everything 查询失败当场降级；对每个结果再做一次读权限过滤 |
| `everything.provider.ts` | 把过滤、排序、分页下推给 Everything；**安全边界**：每个返回路径用 `Vault.adopt` 重新验证在根目录内、排除隐藏条目、非递归时只保留直接子项 |
| `walk.provider.ts` | 在 worker 线程里广度优先遍历，多词 AND、按扩展名过滤，结果上限后标记 `approximate` |
| `provider.ts` | `SearchQuery` / `SearchPage` / `SearchProvider` 接口 |
| `routes.ts` | `GET /search`（`q` 与 `type` 至少一个；只有 `type` 时即"此目录下所有图片/视频/音乐"）、`GET /media/:kind`、`GET /media/:kind/random`、`GET /system/search-status`（仅管理员：Everything 的地址与健康状况） |

Everything 的配置：在 *Tools → Options → HTTP Server* 启用，监听地址**必须是 `127.0.0.1`**（它自己不做鉴权，暴露出去就是第二扇没锁的门），建议也设用户名密码；然后在 `.env` 设 `HEARTH_EVERYTHING_URL` / `_USERNAME` / `_PASSWORD`。可用 `curl -u user:pass "http://127.0.0.1:8081/?s=test&j=1&c=3"` 验证。

### 3.4 Kiln —— 内容与媒体

| 文件 | 职责 |
|---|---|
| `stream.service.ts` | 原始字节 + 单段 Range（多段请求回整个实体）；按媒体类别选读缓冲大小；请求关闭即销毁读流；除 PDF 外一律带 `Content-Security-Policy: sandbox`，直接打开的 .html/.svg 不能以用户会话执行脚本。内联返回时也带 `Content-Disposition: inline; filename=…`（浏览器的 PDF 查看器用它作标题）。`sendGenerated` 用于 Hearth 自己生成/持有的文件；`contentDisposition` 带 ASCII 回退 |
| `range.ts` | Range 头解析 |
| `subtitle.service.ts` | 字幕转 WebVTT 并落盘缓存。从容器里取一条字幕要读完整个文件（10 GB 的片子要几十秒），所以第一次请求时一遍取出全部文本字幕，之后换任何语言都是瞬间；同一文件的并发请求共用一个任务，浏览器放弃等待也不取消它；图形字幕（PGS/VobSub）无法转换，不提供 |
| `thumbnail.service.ts` | 缩略图（磁盘缓存命中直接返回；要解码的经一个 Gate，同时最多每核一个，排队时请求被放弃就不开始）：图片直接 sharp；视频取片长 15% 处（3 秒到 10 分钟之间），再用 ffmpeg `thumbnail` 滤镜从其后 60 帧里挑最有代表性的一帧，避开片头 logo、黑场与转场；音频取内嵌封面，没有则在同目录找 cover/folder/front 等命名的图、再找 Scans/Artwork 等子目录、最后取第一张图；PSD 走 worker、漫画/EPUB/Kindle 书走封面 worker；缓存键含 `THUMBNAIL_REVISION`（`@hearth/shared`，生成方式变了就加一）、绝对路径、mtime 与大小；同一个键也作 HTTP ETag（`etag()`），带版本参数 `v` 的请求可长期缓存，不带的每次协商；"没有图"返回 null（路由回 204，且不许缓存：服务端学会读新格式后，文件没变也可能有图了） |
| `folder-cover.service.ts` | 文件夹封面：在文件夹内（最多两层、每层最多 6 个子目录）找第一个可做封面的文件，跳过横版"书衣"；按目录 mtime 记忆 |
| `text.service.ts` | 读文本：用 `lib/charset` 探测编码（中日韩旧编码能直接识别，不再一律猜成 Windows-1252），可手动指定；超过上限只读开头；写回时保持原编码 |
| `comic.service.ts` | 漫画：按路径+mtime+大小作缓存键，一次解包到缓存目录，之后每页都是普通文件读；并发打开同一本只解一次；页名必须在清单里 |
| `archive.service.ts` | 压缩包：列目录（上限默认 5,000 条，判断"是否全是图片"）与读取单个成员（上限默认 64 MB；两项都随设置即时生效）；加密成员、损坏或不支持的包给出明确的 400；zip/rar 之外的格式明确提示下载 |
| `document.service.ts` | Office 转 HTML（worker）后按白名单净化（拒绝 `//host` 这类无协议地址）。HTML 有两种呈现：**单页**（`renderHtml`，不用本地文件时）——按页面声明的 charset（没有则探测）解码后净化，保留 `<style>` 与老网页的表现型写法（`<body bgcolor>`、`<font>`、`<center>`、表格属性），本地文件一律去掉，外部图片默认禁止并计数，`#` 链接留在页内、外链开新标签，`data:` 只留给图片（框架、嵌入物一律不收）；**站点**（`renderSitePage`，用本地文件时）——相对地址照留（在站点路径下自然解析），框架集、样式表、图像映射、指向本地其他页的链接（含指向框架名的 target）都保留；允许脚本时原样发送（脚本能跑时净化没有意义，隔离靠 sandbox 与 CSP），否则净化；只要页面里有东西会运行（脚本或 Ruffle）就整页进 sandbox，并在 `<head>` 最前面注入框架导航助手（`site-navigation.ts`），Ruffle 开启时再注入加载器。`indexPage` 找文件夹的入口页，`ruffleFile` 取自托管 Ruffle 的文件（不允许跳出其目录） |
| `background.service.ts` | 壁纸：只从 `HEARTH_BACKGROUNDS_DIRECTORY` 列出的文件里选，按名单匹配，不做路径运算 |
| `routes.ts` | 把下面两组路由挂在同一个实例上（钩子与装饰器与原来一致） |
| `media.routes.ts` | 给 `<video>`/`<audio>`/`<img>` 的字节：`/media/raw`、`/media/probe`、`/media/transcode`、`/media/subtitle`、`/thumbnail` |
| `document.routes.ts` | 由前端渲染的文件：`GET/PUT /content`、`/comic`、`/comic/:key/:page`、`/archive`、`/archive/entry`（文本成员转成 UTF-8 并声明 `charset=utf-8`，所有成员带 sandbox 头）、`/office`、`/backgrounds`、`/background` |
| `site.routes.ts` | `GET /html-proxy`：不用本地文件时回单页 HTML；用时为该页所在文件夹签一个站点令牌，回站点地址与是否 sandbox。`GET /site/:token/*`：把一个文件夹当作站点提供。路径先把反斜杠当作分隔符再检查是否仍在令牌的文件夹内（`inFolder`；否则 `..\..` 会在检查时像一个文件名、解析时却跳出文件夹）；读权限在取到最终文件（含目录的 index 页）之后检查。令牌放在路径里（框架是不透明源、没有会话 cookie 可带，放在路径里页面的相对地址也能原样解析），由 Warden 签发、限定该文件夹及以下，并按签发用户的文件夹规则再检查读权限；目录取 index 页；HTML 交给 `renderSitePage`，其余文件走 `streams.send`（Range、sandbox 头）；带 `?hearth=video` 且开启了"播放嵌入的视频"时先探测（结果按路径 + mtime + 大小记住，因为 `<video>` 会对同一文件发好几次请求）：浏览器能直接播的原样发送（`.mov` 改标为 `video/mp4`，否则 Chrome 不认），不能播的（MPEG-4 Part 2、WMV 等）走现有的 ffmpeg 转码，输出分片 MP4；`__ruffle/` 下是 Ruffle 自己的文件。CSP：只许从本机取（管理员允许外部资源时加上网络），有东西运行时加 `sandbox allow-scripts allow-popups…`（无同源）；带 `Access-Control-Allow-Origin: *`，因为 Ruffle 从不透明源 fetch 影片与 .wasm。令牌含文件夹路径，较长，所以 Fastify 的 `maxParamLength` 调到 4096 |
| `embedded-video.ts` | 老网页为 QuickTime / Windows Media 插件写的视频（`<embed src="x.mov" type="video/quicktime">`，或 `<object>` 里 `<param name="URL">`、内含的 `<embed>` 后备）改写成 `<video controls>`：保留宽高，自动播放与循环按原参数（插件默认自动播放），地址保持相对并加上 `?hearth=video` 标记；Flash 的 `<object>`、外站与根路径的文件不动。只认这两种写法，用模式匹配而非解析器，所以对原样发送的（允许脚本的）页面同样适用 |
| `site-navigation.ts` | sandbox 里的框架不能导航兄弟框架和祖先（浏览器改为开新标签），老站的"左侧菜单 `target="main"`"和 `_top` 因此失效。助手拦下这类点击，用 `postMessage` 逐层上传：拥有该名字框架的页设置它的 src（页面可以设置自己子框架的 src），`_parent` 由父页导航自身，到达查看器的（`_top`、找不到的名字）由查看器在自己的框架里打开；只接受自己子框架发来的消息。无 sandbox 时（净化页，没有能运行的东西）框架之间本来就能互相导航，只把 `_top`/`_parent` 改指查看器的框架（`viewerTarget`），免得替换掉 Hearth 本身 |
| `route-helpers.ts` | `pathQuery()`（"文件路径 + 媒体令牌 + 额外字段"的查询参数校验）、`openFile()`（解析路径、查读权限、确认是文件）、`READ` / `STREAM` 两种路由配置 |

### 3.6 Ledger 与 Hob —— 每个用户的数据

两者分开存储：Ledger 播放时每几秒写一次，Hob 可能一周一次，放一个文件里会让后台写入覆盖别的设备上刚改的偏好。

| 文件 | 职责 |
|---|---|
| `ledger/ledger.service.ts` | `data/ledger/progress/<用户>.json`：路径 → Progress（时间 / 页码 / 定位符 + 百分比），最多保留最近 1,000 条；`data/ledger/sessions/<用户>.json`：路径 → 阅读器自己的会话记录（EPUB 的位置、偏好、书签、高亮），不透明，单条上限 512 KB，最多 300 本。`reprefix` / `forget` 对所有用户、两类数据生效，前缀匹配只落在路径分隔符上（`Anime` 不会误伤 `Anime Movies`）。`migrate()` 把 1.x 的 `<用户>.json`（含已删除的 recent/pinned）迁到新位置 |
| `ledger/routes.ts` | `GET/PATCH /ledger/progress`、`GET/PUT/DELETE /ledger/session?path=` |
| `hob/hob.service.ts` | `data/preferences/<用户>.json`，读写都补齐默认值并丢弃已废弃的键 |
| `hob/routes.ts` | `GET/PATCH /preferences`（未知键被丢弃） |

以路径而非内容哈希为键：Hearth 自己做的移动与重命名都会同步 Ledger；在 Hearth 之外改名则进度丢失——这是有意的取舍，内容哈希对大视频代价太高、对编辑过的文本又会失配。

### 3.8 workers —— CPU 密集任务

每个任务由 `lib/worker.ts` 新开一个线程；promise 失败时重新抛出，父线程收到 `error` 而不是一次静默退出。

| 文件 | 职责 |
|---|---|
| `walk.worker.ts` | 广度优先遍历目录做名字匹配 |
| `comic.worker.ts` | 解出全部图片页，按序号命名（两个章节可能有同名页） |
| `cover.worker.ts` | 只取一本书的封面：漫画取第一张竖版页，EPUB 按 container.xml → OPF → 声明的封面，Kindle 书交给 `kindle-cover.ts` |
| `kindle-cover.ts` | MOBI / AZW / AZW3 的封面：Palm 数据库的记录表 → 记录 0 的 MOBI 头给出第一张图片的记录号 → EXTH 201（封面）或 202（缩略图）给出它在图片中的序号。图片记录就是原样的 JPEG/PNG/GIF，所以只读三小段，与书多大无关；阅读器打不开的旧 Mobipocket 书也有封面 |
| `archive.worker.ts` | 列出 zip/rar 成员或读取其中一个；成员名统一成 `/` 分隔并去掉开头的 `/`、`./`（否则显示成没有名字的文件夹）；加密成员（zip 通用标志位 0、rar 头标志）不解压，直接报告 |
| `office.worker.ts` | docx（mammoth）、doc（word-extractor）、xls/xlsx（每个工作表一节）→ HTML |
| `psd.worker.ts` | PSD 合成图 → PNG |
| `comic-pages.ts` | 三个读压缩包的 worker 共用：什么算一页、自然排序、EPUB 封面定位、只读文件头取图片尺寸、`zipPages`（zip 的图片页，按阅读顺序带解码后的名字）、`openRarPages`（在内存中打开 RAR 并列出图片页）、`readArchiveFile`；`zipEntryNames` 解码 zip 文件名——没有 UTF-8 标志的名字（中文/日文 Windows 打的包）按整包探测出的编码解码，三个读 zip 的 worker 都用它 |

### 环境变量与启动方式

全部可选，默认值让新克隆直接服务 `./example`。完整清单（含说明）见仓库根的 `.env.example`，读取逻辑在 `server/src/config/`。非法值（非数字、负数、未知的日志级别、`USER_RULES` 格式错）在启动时一行说明并退出；根目录不存在不算非法——记一条警告照常启动，盘接上就能用。

**加载顺序**（高 → 低）：进程环境变量 → `.env.development`（仅开发模式）→ `.env`。dotenv 不覆盖已存在的变量，所以按"高优先级先加载"即可（`config/env.ts` 的 `loadEnvFiles`）。

**开发模式**：`npm run dev` 以 `--development` 启动后端（也可设 `HEARTH_MODE=development`），Vite 的 `vite`（mode=development）同样读取 `.env.development`。这个文件随仓库提交、不含任何密钥，把所有限制类参数设为 `0`。启动日志第一行会打印 `mode` 与实际加载了哪些文件。生产（`npm start` / `start.ps1`）只读 `.env`，不受影响。

**运行时设置**：一部分变量（`.env.example` 里标了 `[settings]`）只是启动时的默认值——管理员可以在设置面板里改，改动立即生效并存进 `runtime.json`，直到在面板里"恢复默认"为止；普通用户既看不到也改不了（接口与页签都只对管理员开放）。哪些变量属于这一类由 `config/settings.ts` 的表决定：仅管理员模式、回收站开关/保留天数/总大小、HTML 的六个开关、目录/搜索条目数、上传大小、文本大小、压缩包条目数与成员大小、Everything 超时、文件夹封面深度与宽度——都是每次使用时现读的。请求体大小、限流、会话寿命、写进路由 schema 的长度等在启动时就固定，仍只在 `.env` 里改、重启生效。

**限制类参数的统一约定**：一律是非负整数，**`0` 表示不限**，在代码里表示为 `Infinity`（`envLimit`），各处直接与之比较，不需要特判；JSON Schema 里的上限在不限时整个去掉（`lib/limits.ts` 的 `maxItems` / `maximum`），Fastify 的 body 上限用最大安全整数代替，"永不过期"的令牌与票据在接口里返回 `expiresAt: null`，会话在存储里记 `expiresAt: null`。另有三个**保护项**（`envPositive`：Everything 单次超时、文件夹封面的扫描深度与宽度）只接受正整数、没有"不限"，开发模式也不放开——放开只会让服务端无限等待或把整个盘扫一遍。开发阶段本地 `.env` 也把全部限制类参数写成 `0`（`start.ps1` 只读 `.env`），保护项写明默认值；`.env.example` 仍列出各自的默认值。`test/server/config-limits.test.ts` 保证三件事始终一致：代码里每个 `envLimit` 都写进了 `.env.example`、在 `.env.development` 里都是 `0`、加载开发值后配置里的每个上限都是 `Infinity`。

| `npm start` | 以生产模式运行已构建的后端（`node server/dist/main.js`），不含 Caddy |
| `.\start.ps1 [-Build] [-NoCaddy] [-Bind :30709]` | 生产：检查依赖与构建产物，启动后端与 Caddy（`-NoCaddy` 时由共享网关占用端口），任一子进程退出即全部停止 |
| `npm test` / `npm run typecheck` / `npm run lint` / `npm run format` | 测试 / 类型检查 / ESLint / Prettier（`format:check` 只检查） |

`caddy-env.ps1` 从进程环境或 `.env` 推导 Caddy 需要的变量：后端上游（`HEARTH_PORT`）、`web/dist` 路径、`HEARTH_API_PREFIX`、`HEARTH_WEB_PREFIX`。`Caddyfile.snippet` 用 `{$VAR:默认值}` 引用它们（已用 Caddy 2.6.4 验证默认前缀与自定义前缀两种情况）。注意：在 2.6.4 下，`CADDY_BIND` 与 `HEARTH_WEB_ROOT` 未设置时默认值不生效，所以要经 `start.ps1`（它总会设置）来启动 Caddy，不要直接 `caddy run`。

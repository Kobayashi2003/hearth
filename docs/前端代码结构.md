## 一、总览

Vite 7 + React 19 + TanStack Router / Query + Tailwind CSS 4 + Radix（Dialog、DropdownMenu、Switch）+ lucide 图标，TypeScript。自有代码约 6,800 行；另有原样复制进来的 EPUB 阅读器约 41,000 行（`src/vendor/epub-reader/`）。

产物是纯静态文件，由 Caddy 直接吐出，没有前端服务器进程。几条贯穿全局的约定：

- **浏览状态全在 URL 里。** 当前目录、排序、搜索词、搜索范围、类型过滤都是 hash 路由的 query（`#/?path=…&sort=…&q=…`）。后退 / 前进像文件管理器一样工作，任何一屏都能收藏或粘贴复现。用 hash 路由是因为应用挂在一个运行时才知道的前缀下（`/hearth/`），不需要服务端重写规则。
- **偏好属于人，不属于浏览器。** 主题、密度、视图等存在服务端（Hob），换设备也一样；本地只存一份镜像，供 `index.html` 里的内联脚本在首帧前设置主题，避免深色用户每次打开先闪一下白。每个浏览器自己的便利（音量、阅读器排版、换行开关）才放 localStorage。
- **进度属于人。** 视频/音频时间、漫画页码、文本滚动位置、EPUB 阅读会话都写进服务端 Ledger，手机上能接着桌面看。
- **重的东西懒加载。** 每种查看器都是独立 chunk；EPUB 阅读器、代码高亮（shiki 与各语言语法）只有打开对应文件才下载。
- **API 地址固定在根下 `/hearth-api`**（可用 `<meta name="hearth-api-base">` 覆盖），资源用相对地址，所以同一份构建能挂在任意前缀下。

### 视觉

设计令牌全部在 `styles/app.css`：

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `bg` / `surface` / `sunken` | 石灰墙 `#EEF0EC` | 煤灰 `#16191B` | 底色、浮层、凹陷 |
| `ink` / `ink-2` / `ink-3` | 铸铁 `#23272B` | `#E5E9E6` | 正文 / 次要 / 弱化 |
| `glaze` | 青瓷釉 `#3E7A6B` | `#7FB8A6` | 选中、焦点、主按钮 |
| `ember` | 余烬 `#E0692E` | `#F08A4B` | 只用于火焰标志、"正在播放"、进度条 |
| `stage` | `#0E1011` | 同左 | 所有预览的底 |

字体只用一种：Bricolage Grotesque 可变字体（本地打包，`@fontsource-variable`，不向外部请求），中日文回退到系统字体。页面上唯一"大声"的元素是当前文件夹名：窄体、粗、按视口缩放（`.display-title`）。行高由 `--row` 决定，粗指针（触屏）与细指针各有一个区间，密度偏好选区间的哪一端；`FileList.useRowHeight` 里的数字必须与之一致（虚拟列表需要数字）。

标志（`brand/Logo.tsx` 与 `public/favicon.svg`，两处路径保持一致）：一块青瓷釉面砖，上面是余烬色火焰和浅色炉石——"炉边"的意思，16px 下仍可辨认。

    │   ├── limits.ts         前端的限制参数（HEARTH_WEB_MAX_HIGHLIGHT_CHARS、HEARTH_WEB_PARALLEL_UPLOADS，0 = 不限，构建时读入）

## 三、逐模块

### 3.1 `features/session`、`preferences`、`progress`

| 文件 | 职责 |
|---|---|
| `session/session.tsx` | 会话查询（窗口获得焦点时重查，cookie 过期能及时发现）；`unreachable` 表示根本没连上服务端（网络失败，或代理代为回答的非 JSON 5xx/404——Hearth 自己的错误总是 JSON），`retry` 重查；`can(action)` 只用于界面显隐，服务端独立校验；登录/登出时清掉会话以外的所有缓存 |
| `session/CredentialFields.tsx` | 用户名与密码两个字段，登录页与"新增用户"共用；用途决定密码管理器给出已存的密码还是建议新密码，新用户名还要符合服务端接受的字符 |
| `session/LoginPage.tsx` | 登录页；服务端不在时（打开页面时或点登录时发现）显示排查指引：用 `start.ps1` / `npm run dev` 启动、核对 `HEARTH_PORT` 与 Caddy/开发代理转发的端口、看服务端日志，并可"重试" |
| `preferences/preferences.tsx` | 从本地镜像起步、再以服务端为准；改动先本地生效再 PATCH；把主题、密度写到 `<html>` 的 data 属性 |
| `progress/progress.ts` | 进度读写。写入经过模块级"发件箱"合并（同一路径只留最新），4 秒一发，页面隐藏/关闭时立即发，保证最后一次位置不丢 |

### 3.2 `features/shell` —— 外框

| 文件 | 职责 |
|---|---|
| `AppShell.tsx` | 登录门；Provider 顺序：偏好 → 预览 → 播放器 → 停靠区；≥1024px 侧栏常驻，更窄时是抽屉；壁纸；挂载预览层、迷你播放器与设置对话框 |
| `Sidebar.tsx` | 字标（点回根目录）、根目录切换（管理员且有多个根时；盘没接上的根变灰并注明 not connected，有这样的根时每 30 秒重查一次，接上即可选）、"合集"（此根下全部图片/视频/音乐）、根目录的一级文件夹、用户与设置/登出。切换根目录时丢弃按根内路径缓存的查询（列表、文件内容、探测等）后立即跳转，留在当前合集，不再用旧路径去新根里请求（`useRootSwitch`）。根目录菜单（`RootSwitcher`）与底部用户栏（`UserBar`）是各自的组件 |
| `Dock.tsx` | 底部停靠区：左为迷你播放器、中为选择栏、右为上传面板；窄屏竖向堆叠且选择栏在最下；宽屏从侧栏右侧开始 |
| `shell-context.ts` | 打开设置、打开抽屉、当前根目录名 |

### 3.3 `features/explorer` —— 浏览

| 文件 | 职责 |
|---|---|
| `search.ts` | URL 里的浏览状态（ExplorerSearch：路径、排序、搜索词、文件夹内的范围 scope：here / below、类型、要定位的条目 reveal）与校验；`useRevealInFolder` 跳到某个条目所在的文件夹（清掉搜索与过滤，带上 reveal）；`explorerRoute` 用 `getRouteApi('/')` 取路由，组件不必反向引用 router.tsx（router 引用页面，页面再引用 router 会成环） |
| `shortcuts.ts` | 浏览页的整张快捷键表（纯函数，传入当前状态返回 KeyBinding[]）；Ctrl+K 在任何地方都可用，其余只在浏览页拥有键盘时生效 |
| `commands.ts` | 命令面板（Ctrl+K）的命令表，可写操作只对有写权限的人出现 |
| `ExplorerPage.tsx` | 组装：列表 / 封面视图、选择、键盘、右键菜单、对话框、命令面板、拖放上传、选择栏与上传面板。切换目录或搜索时清空选择；回到上级时光标落在刚离开的文件夹上、"在文件夹中显示"时选中目标并滚到可见（`useLanding.ts`）；点击任何不是条目或控件的地方（条目间隙、行尾、列表下方）都算点空白，清空选择；在空白处右键（或触屏长按）弹出文件夹菜单：新建文件夹、上传、粘贴、全选、刷新 |

| `ViewTools.tsx` | 顶栏右侧：刷新、排序菜单、列表/封面切换、"新建"菜单（可写时） |

### 3.5 `features/preview` —— 预览

同一时间只有一个预览，铺满整个窗口（`stage` 深色底）。浏览器后退键关闭预览而不是离开目录；Esc 关闭；图片、PDF、Office、HTML、Flash 可用 ←/→ 在同类文件间切换（视频、漫画、文本、EPUB 自己用方向键）。

#### EPUB 阅读器的接入

`src/vendor/epub-reader/` 是 `D:\Program\Code\components\src\library\data-display\epub-reader` 的 `core/`、`react/`、`types/` 与 `styles.css`（去掉了只属于演示页的 showcase 样式），**除 `core/extension/model.ts` 一处补了 `override` 关键字以通过本项目更严格的编译选项外与上游一致**。竖排书每章末页无法翻到位的问题（竖排分页时最后一栏下方的页边距不计入可滚动高度，末页被截断）是在 Hearth 里发现的，修复 `ensureWholeVerticalPages`（`core/presentation/renderer/reflowable/dom/layout.ts`）已先在这里验证、再同步回上游并通过上游的 `npm run check`、浏览器交互与视觉基线检查。它有自己的 lint 规则，Hearth 的 ESLint 与 Prettier 都忽略该目录。更新时整体重新复制（不含上游的 README、docs 与 core 的 `.prettierrc.json`）并重新打上 `override` 这一处改动即可；最近一次同步是 2026-10-02。

这次同步带来了 Kindle 支持：`core/epub/archive/kf8-archive/` 把 AZW3（KF8）——以及 MOBI 文件里附带的 KF8 部分——在浏览器里原样拆成 EPUB 包再走同一条加载管线，所以目录、搜索、标记、会话都与 EPUB 一致；没有 KF8 部分的旧 Mobipocket 书与带 DRM 的书由阅读器给出说明。Hearth 这边只是把 `KINDLE_EXTENSIONS`（`@hearth/shared`）也交给 EPUB 查看器，并在服务端读封面。

`EpubViewer.tsx` 负责把它接到 Hearth：

1. 同时下载书的字节（`/media/raw`）和该用户这本书的阅读会话（`/ledger/session`）。
2. 给阅读器一个同步的 `ReadingSessionStorage`：`load` 返回预先取到的记录；`save` 更新内存并在 1.5 秒防抖后 PUT 回服务端，同时按"第几章 + 章内进度"估算百分比写进 Ledger 进度（列表里的进度条来自这里）；`remove` 删除服务端记录。
3. 会话键就是文件路径，所以重命名/移动时 Ledger 的 `reprefix` 会带着它走。
4. 初始页边距设为 6%（阅读器默认贴边）；已有会话里保存的偏好优先。

阅读器自带目录、搜索、书签/高亮/批注、排版与主题设置、全屏和键盘帮助，Hearth 只在它上方保留一条细的顶栏（文件名、下载、全屏、关闭）。

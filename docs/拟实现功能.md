## 零、混乱度：仍超过严格门槛的地方（2026-10-08）

按复杂度 10、函数 60 行的严格口径，还剩 21 个函数略超复杂度（11–17），53 个函数超过 60 行。复杂度主要来自可选链与 `??`（`TextViewer`、`ExplorerPage`、`Sidebar`），或是写在一处更便于核对的安全判断（`linkAttributes`）；长函数主要是 JSX 较长的组件（设置各页、`SelectionBar`、`usePanZoom`、`useSelection`）与 `buildApp`、`loadConfig` 这类装配函数。ESLint 的硬上限（复杂度 30、函数 300 行）离它们都很远，按需要再拆，不为数字拆。

## 三、待定

| 想法 | 为什么还没做 |
|---|---|
| 恢复"多个预览并存 + 最小化到停靠区" | 1.x 有，2.0 简化为一次一个预览、音频单独由迷你播放器承接。如果常常需要一边开着文档一边看另一份，再加回来；数据结构（`PreviewProvider`）改成栈即可 |
| 可拖拽大小的预览窗口 | 同上，用得少时不值得它的复杂度 |
| 悬停预览卡片 / 长按预览卡片 | 2.0 用右键/长按菜单与"详情"代替 |
| 把"固定（Pinned）"作为收藏夹而不是首页展柜 | 展柜已按要求删除；如果需要"常用位置"，更合适的形态是侧栏里的收藏文件夹 |
| 界面中文化 | 目前界面文字是英文（沿用 1.x）。文字集中在各组件里，中文化需要先抽出一个文案表 |
| EPUB 阅读器跟随 Hearth 的深浅主题 | 阅读器有自己的主题体系（出版方/浅/深/护眼……），目前各管各的；可以用 `configureReaderUi` 注册与 Hearth 配色一致的主题并按 Hob 选择 |
| 阅读器会话的冲突处理 | 两台设备同时读同一本书时后写者胜；个人使用下足够，暂不做合并 |
| 缩略图预生成 | 现在是第一次看到时生成；大库第一次打开封面视图较慢（视频缩略图各启动一个 ffmpeg，一屏视频较多时可考虑限制并发） |
| 更准确的 `.ts` 判定 | 现在按 1 MB 阈值区分源码与录像；读文件头（MPEG-TS 每 188 字节一个 0x47 同步字节）更准，但列目录时要多读每个文件 |
| 进度按根目录区分 | Ledger 以根内相对路径为键，两个根里相同相对路径的文件共用一条进度。要分开需给键加根目录前缀并迁移已有数据；多根同名文件少见，暂不改 |
| 选择栏、上传面板、迷你播放器的退场动画 | 它们按条件渲染，退场需要自己的延迟卸载逻辑；弹窗、菜单、抽屉、预览层已有退场 |
| PPTX 预览 | Office 查看器现在只支持 docx/xlsx；pptx 被当作下载 |
| 7z 压缩包 | 只能下载；可以用 7-Zip 命令行列目录与取单个文件 |
| 表格的工作表切换与表头固定 | 多工作表现在上下排列 |
| CUE 分轨 | 整轨 FLAC + .cue 现在当一首 18 分钟的歌；按 cue 显示曲目并跳转会更好 |
| 默认开启文件夹封面 | 番剧/专辑按目录整理时，灰色文件夹格与视频帧并排显得空；开启需要扫描子目录，现在由用户在设置里选 |
| 没有 KF8 部分的旧 Mobipocket 书 | 阅读器只读 KF8；F:\ 里的 MOBI 实测都带 KF8 部分。真遇到纯 MOBI6 的书，可以再考虑服务端用 Calibre 转换作为后备 |
| 站点里用脚本跳转框架 | sandbox 下，`top.location = …`、`parent.frames['main'].location = …` 这类脚本跳转仍被浏览器拦下；链接（含 `target`）已由导航助手处理。真遇到靠脚本导航的站点再考虑在助手里改写这些调用 |
| 直接打开站点里的子页 | 站点令牌限定在所打开页面的文件夹及以下；从入口页进入时没有问题，直接打开 `data/xxx.html` 时它引用 `../` 的资源会被拒绝。可以改为向上找入口页所在的文件夹作为站点根 |
| 转码中的嵌入视频不能拖动 | 转码输出是流，`<video>` 无法跳到中间；这些片段多为几秒到几十秒，从头播放影响不大。需要时可以像视频查看器那样按新起点重启转码 |
| RAR4 的非 Unicode 文件名 | RAR5 与带 Unicode 名的 RAR4 没问题；极老的 RAR4 用本地代码页存名，未处理 |

## 四、明确不做

| 项 | 理由 |
|---|---|
| 同步、备份、多租户 | Hearth 的定位是"在别处访问家里的文件"，不托管文件 |
| 自建搜索索引 | Everything 已经做得更好；非 Windows 或 Everything 不在时目录遍历足够 |
| 以内容哈希作为进度的键 | 大视频算哈希代价太高，编辑过的文本又会失配；以路径为键并由 Hearth 自己的移动/重命名同步 |
| 内置 PDF 渲染器 | 浏览器自带的已经够好 |
| 前端服务端渲染 / 前端服务进程 | 静态文件 + Caddy 直连后端，是为了字节流路径上没有第二个进程 |

## 零、混乱度：仍超过严格门槛的地方（2026-10-08）

按复杂度 10、函数 60 行的严格口径，还剩 22 个函数略超复杂度（11–17），59 个函数超过 60 行。复杂度主要来自可选链与 `??`（`TextViewer`、`ExplorerPage`、`Sidebar`），或是写在一处更便于核对的安全判断（`linkAttributes`）；长函数主要是 JSX 较长的组件（设置各页、`SelectionBar`、`usePanZoom`、`useSelection`）与 `buildApp`、`loadConfig` 这类装配函数。ESLint 的硬上限（复杂度 30、函数 300 行）离它们都很远，按需要再拆，不为数字拆。

## 零·一、React Compiler 规则（2026-10-09）

`eslint-plugin-react-hooks` 7 带来的规则（`set-state-in-effect`、`refs`、`immutability`、`static-components`）与 `react-refresh/only-export-components` 现为 warn，剩 39 条，几乎都在升级前写的代码里：effect 里复位状态（改为渲染中比较前值）、渲染时读写 ref（键盘表、媒体会话、平移缩放等"最新值"写法）、在 hook 外改对象、与组件同文件导出的 hook 与常量。逐个改写后把这些规则恢复为 error。

## 一、待验证（代码已写，未实机走过）

2026-10-08 手机适配只在模拟器里走过：安全区（刘海、灵动岛、底部横条）、iOS 键盘与对话框、输入框不放大、添加到主屏幕后的独立窗口，都要在真机上确认。EPUB 阅读器（复制来的组件）、PDF、Office 文档、上传面板在手机上还没有逐屏看过。

2026-10-08：视频播放"帧率低"的改动（抽帧单线程低优先级、并发减半、视频上的箭头去掉背景模糊）在自动化浏览器里量不出差别（那里即便是裸 `<video>` 也丢约 14% 的帧），需在真实浏览器里复看；若仍卡，先在新标签直接打开原文件对比，并看 `chrome://gpu` 的视频解码是否为硬件加速。

2026-10-15：用局域网 IP 以 HTTP 打开时（不是安全上下文），上传已能用，但 EPUB 阅读器（复制来的组件）解混淆字体要用 `crypto.subtle`，在这种情况下不存在，带混淆字体的书可能打不开或字体缺失；剪贴板写入等也受同样限制。手机长期使用建议走 HTTPS（Caddy 可签证书）。进度条的预览帧与拖动只在自动化浏览器与模拟手机里走过，真机与转码视频待复看。

2026-10-16：侧栏的拖动、收起与收藏夹只在自动化浏览器与模拟手机里走过；Firefox 里 Ctrl+B 原本打开书签侧栏，页面能否拦下要实测。整轨专辑只用生成的 FLAC 试过；音频转换（APE、TTA、WavPack、WMA 等）只用 ffmpeg 与 Chromium 分别验证过，没在完整页面里播过，也没在 Safari 上试过转出的 FLAC 流。EPUB 的"Hearth"主题在出版方样式较重的书上效果待看。

2026-10-24：压缩包里的文件在内层用平常的查看器打开、压缩包的封面视图，都只经单元测试与真实 worker 验证，没在页面里点过。已知不足：包里的网页只能单页显示（站点模式要用到它周围的文件，而它们在包里）；包里的 EPUB 不保存阅读位置；压缩包仍整包读入内存，几 GB 的包会很吃内存——要改需换按需读取的 zip 库（如 yauzl）。

2026-10-07：缩略图队列只在开发模式（React 严格模式会让每个图块挂载两次）下用生成的 900 张图实测过；你的媒体盘（E/F/H/I/J）当时都不在线，真实库与生产构建下的表现待重新走一遍。全部根目录都不在时，Hearth 停在默认根上；若另一个根先接上，要管理员手动切过去（不会自动换根，以免切走后再也回不来）。

## 三、待定

| 想法 | 为什么还没做 |
|---|---|
| 恢复"多个预览并存 + 最小化到停靠区" | 1.x 有，2.0 简化为一次一个预览、音频单独由迷你播放器承接。如果常常需要一边开着文档一边看另一份，再加回来；数据结构（`PreviewProvider`）改成栈即可 |
| 可拖拽大小的预览窗口 | 同上，用得少时不值得它的复杂度 |
| 悬停预览卡片 / 长按预览卡片 | 2.0 用右键/长按菜单与"详情"代替 |
| 阅读器会话的冲突处理 | 两台设备同时读同一本书时后写者胜；个人使用下足够，暂不做合并 |
| 缩略图预生成 | 现在是第一次看到时生成；大库第一次打开封面视图较慢（视频缩略图各启动一个 ffmpeg，一屏视频较多时可考虑限制并发） |
| 更准确的 `.ts` 判定 | 现在按 1 MB 阈值区分源码与录像；读文件头（MPEG-TS 每 188 字节一个 0x47 同步字节）更准，但列目录时要多读每个文件 |
| 进度按根目录区分 | Ledger 以根内相对路径为键，两个根里相同相对路径的文件共用一条进度。要分开需给键加根目录前缀并迁移已有数据；多根同名文件少见，暂不改 |
| 选择栏、上传面板、迷你播放器的退场动画 | 它们按条件渲染，退场需要自己的延迟卸载逻辑；弹窗、菜单、抽屉、预览层已有退场 |
| PPTX 预览 | Office 查看器现在只支持 docx/xlsx；pptx 被当作下载 |
| 7z 压缩包 | 只能下载；可以用 7-Zip 命令行列目录与取单个文件 |
| 表格的工作表切换与表头固定 | 多工作表现在上下排列 |
| 默认开启文件夹封面 | 番剧/专辑按目录整理时，灰色文件夹格与视频帧并排显得空；开启需要扫描子目录，现在由用户在设置里选 |
| 没有 KF8 部分的旧 Mobipocket 书 | 阅读器只读 KF8；F:\ 里的 MOBI 实测都带 KF8 部分。真遇到纯 MOBI6 的书，可以再考虑服务端用 Calibre 转换作为后备 |
| 站点里用脚本跳转框架 | sandbox 下，`top.location = …`、`parent.frames['main'].location = …` 这类脚本跳转仍被浏览器拦下；链接（含 `target`）已由导航助手处理。真遇到靠脚本导航的站点再考虑在助手里改写这些调用 |
| 直接打开站点里的子页 | 站点令牌限定在所打开页面的文件夹及以下；从入口页进入时没有问题，直接打开 `data/xxx.html` 时它引用 `../` 的资源会被拒绝。可以改为向上找入口页所在的文件夹作为站点根 |
| 转码中的嵌入视频不能拖动 | 转码输出是流，`<video>` 无法跳到中间；这些片段多为几秒到几十秒，从头播放影响不大。需要时可以像视频查看器那样按新起点重启转码 |
| RAR4 的非 Unicode 文件名 | RAR5 与带 Unicode 名的 RAR4 没问题；极老的 RAR4 用本地代码页存名，未处理 |

## 四、明确不做

| 项 | 理由 |
|---|---|
| 界面中文化 | 2026-10-17 决定不做：界面文字保持英文 |
| 同步、备份、多租户 | Hearth 的定位是"在别处访问家里的文件"，不托管文件 |
| 自建搜索索引 | Everything 已经做得更好；非 Windows 或 Everything 不在时目录遍历足够 |
| 以内容哈希作为进度的键 | 大视频算哈希代价太高，编辑过的文本又会失配；以路径为键并由 Hearth 自己的移动/重命名同步 |
| 内置 PDF 渲染器 | 浏览器自带的已经够好 |
| 前端服务端渲染 / 前端服务进程 | 静态文件 + Caddy 直连后端，是为了字节流路径上没有第二个进程 |
